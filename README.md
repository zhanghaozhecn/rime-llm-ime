# rime-llm-ime — 会用 AI 重排候选的小狼毫

## 快速开始（以朙月拼音为例，约 5 分钟）

> 目标：让 **朙月拼音 `luna_pinyin`**（Rime 自带默认方案）用上 LLM 候选重排。换别的方案同理：第 4 步的「编码匹配」按该方案的码长改。

1. **装安装包**：到 [Releases 最新版](https://github.com/zhanghaozhecn/rime-llm-ime/releases/latest) 下载 `weasel-llm-setup-<日期>.exe` 双击（未签名——SmartScreen 弹窗选"更多信息 → 仍要运行"）。全新机器**无需**先装官方小狼毫；已有官方小狼毫则原地升级、不动注册表。装完向导不再问模型（下载在设置界面里）。
2. **打开设置**：托盘小狼毫 → 右键 → **「LLM 重排设置」**（本来就在运行的应用要重启/注销后才有这个菜单项）。
3. **方案接入**：`方案文件` 选 **`luna_pinyin.schema.yaml（程序）`**（带「（程序）」= 小狼毫自带的预装方案；保存时会先复制到用户文件夹再改，原件不动）。
4. **改参数 + 下模型**：
   - `触发条件` → `编码匹配` 填 **`.+`**（朙月拼音码长 1~6 不等，默认 `.{4}` 不会触发）。
   - `总控` → 点 **『下载模型』**（约 508 MB，ModelScope，断点续传）。
5. **点『保存并生效』** —— 写进该方案的 `llm_rerank:` 节并自动重新部署（缺组件行/配置节时会自动补齐）。
6. **验证**：**连打两个词**——先打 `nihao` 选「你好」上屏，再打 `shijie`，第二个词起重排生效（候选顺序按上文语义变化）。**光标前没有文字时不重排**：重排至少要 1 个上文 token，刚装好（或空文档、刚切窗口）打第一个词时上文为空，引擎直接按原顺序放行，属预期。想确凿看到"上文来源/内容 + 每个候选的分数"：开 [实时调试窗口](#实时调试窗口)（托盘右键 → "LLM 调试窗口"；需在设置界面勾选"诊断日志"并保存生效）。没生效：托盘小狼毫 → **重新部署**。

后续微调都在同一页：改 `推理规模`（上文 token / 候选数 / **CPU 线程——点右边『实测线程数』让本机实测给推荐值**）与 `候选排序融合`（词长权重；词频 β 为内置常数 8，2026-11-05 起不再提供配置）→ **保存并生效**；不想用了点 **『剥离』**（就在保存右侧：组件行与配置节一起删，自动重新部署）。

---

LLM 候选重排**源码级集成**进 RIME 小狼毫：本地小语言模型（Qwen3.5-0.8B，约 500MB）依据你正在输入的句子实时给候选排序——刚打过的字决定下一个词谁排第一。全离线运行，无云端无账号，普通 CPU 即可（参考延迟 ~43ms/键）。

## 安装

### 安装包（推荐）

1. 到 [Releases 最新版](https://github.com/zhanghaozhecn/rime-llm-ime/releases/latest) 下载 `weasel-llm-setup-<日期>.exe`（约 10MB）双击（未签名——SmartScreen 弹"Windows 已保护你的电脑"时选"更多信息 → 仍要运行"）。全新机器无需先装官方小狼毫；已有官方小狼毫则原地升级、不动注册。系统要求：Windows 10 或更高（更早版本未验证）
2. 安装向导**不再询问模型下载**（2026-10-01 定案：下载功能统一挪进配置 GUI）：装完在托盘「LLM 重排设置」→ **总控** → 点**「下载模型」**（约 508MB，ModelScope，curl 断点续传；落点 = 模型路径框，留空 = `%APPDATA%\Rime\Qwen3.5-0.8B-Q4_K_M.gguf`）。**安装过程不写任何配置文件**
3. **在要启用的方案里加组件与配置节**（一次性，三选一）：托盘右键 → "LLM 重排设置" → 选方案点"保存并生效"（缺组件行/配置节时会自动补齐：幂等插入 `llm_filter` + 写入 `llm_rerank:` 配置节 + 自动重新部署）；或运行安装目录下的 `schema_add.ps1`（右键"使用 PowerShell 运行"，交互同上、另支持 CLI 自动化）；或按下文"方案接入"手动加。之后托盘右键 → **重新部署**（用 GUI 保存则自动）
4. 若还没下模型：托盘右键 → **"LLM 重排设置"** → 总控 → 点**「下载模型」**（或"浏览…"选已有的 `.gguf`；状态行会提示文件是否存在）→ 点**保存并生效**（写入该方案并自动重新部署）
5. 验证：**先上屏一个词**（光标前无文字时不重排——刚装好打的第一个词必然保持原序），再打满 4 码观察候选顺序按上下文变化；确凿验证开 [实时调试窗口](#实时调试窗口)（托盘右键 → "LLM 调试窗口"）看逐候选分数

> 已运行的应用需重启（或注销重登）托盘里才有新菜单项；重装/修复 = 重跑安装包（幂等）；输入法图标消失（罕见）→ 右键安装目录下的 `repair_tsf.ps1` → "使用 PowerShell 运行"。

### 设置界面

托盘右键 → "LLM 重排设置"。**单页界面**（与插件版安装器同构）：**方案接入**（方案文件下拉）→ **总控**（启用开关 + 模型路径 + **下载模型** + 模型状态）→ **触发条件** → **推理规模** → **候选排序融合** → **诊断日志** → 底部 **保存并生效 / 剥离 / 关闭**（底色与插件版统一为白）。

**配置写在方案里**：先在上面选方案文件，再改参数，点"保存并生效"写进该方案的 `llm_rerank:` 节并**自动重新部署**（部署完成即生效）。**"保存并生效"是自适应的**：方案还没接入（缺配置节 / 缺 `llm_filter` 组件行 / 残留插件版组件行）时会先剥净再补齐组件行 + 写入配置节（原「接入 LLM」按钮已并入这里），已接入则只重写配置节；无配置节的方案默认勾选「启用」，点一次保存即完成接入。**"剥离"就在保存按钮右侧**，负责整体移除组件行与配置节。**"下载模型"在模型路径那一行**（curl 断点续传，失败保留 `.download` 分片可续传）。**方案下拉列出两处** `*.schema.yaml`：**用户文件夹** `%APPDATA%\Rime`（可写、Rime 优先）与**程序文件夹** `<小狼毫安装目录>\data`（预装方案 luna_pinyin / cangjie5 / bopomofo …，带「（程序）」后缀）；**打开下拉即重扫两处**（外部新增/删除方案后无需手动刷新），界面没有未保存改动时还会重读当前文件。预装方案**写入前会自动复制到用户文件夹**（写程序文件夹既要管理员、又会被下次升级覆盖），程序文件夹里的原件不受影响。若方案文件在界面读入后被外部改过，保存前会弹一次确认。界面**不留日志框**：正常只看状态行，出错才写 `WeaselLLMSetup_error.log`（程序所在目录；该目录不可写时回退 `%APPDATA%\Rime\`）。所有参数可选，默认值开箱即用；每项右侧「?」悬停看说明：

| 参数 | 默认 | 说明 |
|------|------|------|
| 启用 LLM 重排 | 关 | 总开关（写进方案节；关 = 卸载模型释放内存） |
| 模型路径 | `%APPDATA%\Rime\` | **下拉框**（可手输）：列出本机扫描到的 `.gguf`（Rime 用户目录 + `%USERPROFILE%\gguf_models`），"浏览…"选任意文件；状态行实时显示文件存在性/大小——**小于 100MB 显示"模型可疑"**（半截模型会让重排静默失效）。右侧**「下载模型」**就地下载（ModelScope 断点续传，失败留 `.download` 分片可重试；新下载会先结束上次遗留的 curl 进程）。**必须是绝对路径**（`D:\…` / UNC），相对路径保存会被拒绝；默认路径跟"用户目录"（`RIME_LLM_USER_DIR` → 注册表 `RimeUserDir` → `%APPDATA%\Rime`） |
| 编码匹配 | `.{4}` | **正则，全串匹配**——决定哪些编码触发重排。语法与语义同 Rime 自身 `speller/auto_select_pattern`（同一 boost::regex 引擎）：仅 4 码 `.{4}`｜4 码以上 `.{4,}`｜3-4 码 `.{3,4}`｜指定首码的 4 码 `[abcde]{4}`｜任意长度 `.+`｜**留空 = 不限制**。模式非法时回退默认并在 `rime_llm_filter_log.txt` 留痕。取代旧的"最小/最大编码长度"（旧键读取时忽略、保存后消失） |
| 两码整句 | 关 | 开启后词长==⌊码长/2⌋ 的候选作为一组直接优先（组内按融合分降序、同分稳定），其余候选按融合分降序在后。**两码一字整句方案专用**——整句模式下候选可能是长串编码切分后词的拼接，此项使满句长候选优先。双拼/五笔/郑码等定长整句方案可开启，字词方案保持关闭（2026-11-07 取代原"预期词长权重"加成） |
| debug_fusion | 关 | 勾选"诊断日志"：逐块把评分→词频→融合→满长标记全过程写入用户目录 `rime_llm_debug.txt`（与插件版同名同格式；commit 行无码字段、reset 行按代次记）；**同一开关同时驱动[实时调试窗口](#实时调试窗口)的实时数据流**；诊断排障用，平时关闭 |
| 上文 token 上限 | 10 | 截取的上文 token 数（最少上文 token 固定 1，不再是配置项） |
| 候选数上限 | 5 | 参与打分的候选数 |
| CPU 线程数 | 4 | 推理线程数，不超过物理核数；点行内『实测线程数』本机实测 4~8 线程给推荐值（<5 线程直接取最大） |

> **重排分两层（2026-11-07 起生产语义）**：层1 全体候选先按 用户词频打分重排（同分保引擎序），取前 `max_candidates` 名进 LLM 评分；无 CE 分的候选回退后两项和；其余候选按层1 序透传 → 层2 对前 k 名做下述三项融合。选重率（用户真实语料）由 3.73% 降至 1.96%（k=5）。
> **内置常数（2026-11-05 起不提供配置；2026-11-06 v3 六维联合标定）**：词频权重 `β=12`、词频衰减 `τ=400`（半衰期 ≈277 次上屏）。
> 标定产物不暴露给用户——旧方案的 `freq_beta` 行在保存 / 重跑接入时自动剥除。

GUI 与接入助手写的都是**方案内的 `llm_rerank:` 配置节**（`%APPDATA%\Rime\*.schema.yaml`），键名与上表一致；**两版（本版与插件版 rime-llm-rerank）的方案配置节完全相同，只有组件行不同**（本版 `- llm_filter`，插件版 `lua_processor@*llm_processor` + `lua_filter@*llm_filter`）——切换版本时先接入会自动剥掉另一版组件行。参数没有内置默认之外的第二层来源（2026-09-30 起取消了旧的全局 `%APPDATA%\Rime\llm_rerank.yaml`；该文件若还在会被忽略，只有设置界面在"方案节没配 model_path"时会读它一次以迁移模型路径）。改动保存后自动**重新部署**生效：改模型路径按新路径加载；关闭开关即卸载释放内存。

### 词频与词长融合公式

内置常数 `β=12`（词频权重）按统一结合公式在**对数域三项相加**（用户 bigram 项已于 2026-11-08 退役——cohort 生产量级评测实证其在真实用户龄几乎无贡献，历史结论见研究资料库）：

```
fused(w) = score(w) + β · log(1 + eff(w)) + log( p1(w) )
p1(w) = (uni[w]+1) / (n_seen+20000)
```

- `score(w)` = 原始 LLM 分，即候选词在上文条件下的负交叉熵（−CE，对数概率域，越大越好）
- `eff(w)` = Rime 同源的时间衰减计数（librime `algo::formula_d`，与引擎调频 userdb 同一公式）：

```
提交（每次含中文上屏，全局 tick ← tick + 1）:   dee ← 1 + dee · exp((t_w − t) / τ)
查询（打分时刻）:                               eff = dee · exp((t_w − t) / τ)
τ = 400 tick，半衰期 ≈ 277 次提交（v3 2026-11-06 六维联合标定：用户域标定 → wiki 平台内就近点；旧值 800 出自 2026-11-02）
```

- `dee` = 该词的衰减计数，`t_w` = 该词最后提交的 tick，`t` = 当前全局 tick。近期常打的词 eff 高，久未使用自动消退
- **两码整句**（`two_code_sentence`，默认关闭）：开启时在融合排序之后追加一次满长组优先重排——词长 == ⌊码长/2⌋ 的候选一组置顶（组内按融合分），即原 elw 加成取极限的等价直接实现（2026-11-07 起取代 elw·span 间接量）
- 词频由上屏自动统计（RIME 用户目录 `user_freq.tsv`，仅中文词，每 20 词落盘；格式 `词\t累计\tdee\ttick`，首行 `#tick=N`）
- 用户累计 unigram 由上屏自动统计（RIME 用户目录 `user_bigram.tsv`，文件名历史沿用：仅含中文字符的词、原始计数不衰减，每 20 词落盘；行 `u\t词\t次数`，首行 `#n=N`；与插件版同格式共用。曾配套的用户 bigram 项已于 2026-11-08 退役——旧文件里的 b 行读取时忽略、下次落盘自然剥除）
- 标定与设计取舍的完整记录见本地研究资料库 `freq-fusion-research.md`

**调试窗口的列名对照**（2026-11-11 起每格 = `得分=计算过程`，公式直接体现在数据里；见 [实时调试窗口](#实时调试窗口)）：

| 公式里的量 | 窗口列 | 格内样式（等号左 = 分数，右 = 计算过程）|
|---|---|---|
| `score(w)` | `CE` | `-28.075=-(1.00·14.010+1.05·10.130+0.45· 7.617)`（CE 分值 = 负的加权连加，分量是原始交叉熵）|
| `β·log(1+eff(w))` | `衰减词频分` | `13.565=12·ln(1+2.11)`（2.11 = 衰减计数）|
| `log(uni(w)+1)` | `累计词频` | `2.197=ln(8+1)`（8 = 累计次数；2026-11-11 起公式不含分母——原 log p1 的分母是窗内常数、排序不变量）|
| `fused(w)` | `总分` | `-38.095`（纯分值，置前三列之前——三项已各自带过程）|

命名规则：**原始证据叫「计数」，进公式的叫「得分」**——一个名字不会同时指两者。
层1 预排分不再单独展示——它 = 衰减词频分+累计词频。


### 方案接入（llm_filter 为显式组件）

`llm_filter` 遵循 Rime 惯例：**方案在 `engine/filters` 里显式列出才参与重排**，未列出的方案完全不受影响。位置由方案与其他 filter 的先后关系决定（重排拿到的是其上方 filter 处理过的候选；一般放在简化/去重类 filter 之后）：

```yaml
# <方案>.schema.yaml
engine:
  filters:
    - simplifier
    - uniquifier
    - llm_filter      # 加这一行，位置按需调整

llm_rerank:            # 参数节（GUI / schema_add.ps1 自动写入，键名同设置界面）
  enabled: true
  code_pattern: '.{4}'
  max_tokens: 10
  max_candidates: 5
  cpu_cores: 4
  two_code_sentence: false
  debug_fusion: false
  # model_path: <绝对路径；留注释 = 默认 %APPDATA%\Rime\Qwen3.5-0.8B-Q4_K_M.gguf>
  # 词频权重 β=8 / τ=800 为内置常数（2026-11-05 起退出配置面；旧 freq_beta 行保存时自动剥除）
```

### CPU 线程数（`cpu_cores`）

默认 4 只是 GGML 默认值，最优值随机器而变。设置界面「推理规模」→ CPU 线程数右边的**『实测线程数』**：用本机模型实测 **4~8 线程**的每键延迟（约 30 秒，期间请勿打字），弹框给出逐档延迟表 + 推荐值，点「是」把推荐值填进输入框，再点『保存并生效』应用（自动重新部署）。

- **推荐口径**：取最优延迟 × 1.05 以内**最快**（线程数最小）的档位，且不超过本机物理核——超出物理核的线程是 SMT 兄弟线程，对这个负载几乎不涨分
- **本机不足 5 逻辑核不做实测**，直接取最大线程数
- 实测不写盘：只填输入框，落盘仍走『保存并生效』；关掉界面会一并结束实测进程
- 工具本身是 `bench_threads.exe`（与本设置程序同目录；规范源在插件版仓库 `..\rime-llm-rerank\cpp\bench_threads.cpp`），也可命令行单跑：`bench_threads.exe [模型路径] [--trials N]`

## 常见问题

- **Win+Space 没有小狼毫**：设置 → 时间和语言 → 语言 → 中文 → 键盘 → 添加键盘 → 小狼毫
- **某些应用里调试窗口来源显示 `rime`（上屏历史）**：该应用不支持光标文本采集（WPS 表格编辑态、部分 32 位应用），自动用上屏历史，属正常回退
- **WPS 里调试窗口来源显示 `com`**：WPS 文字/演示经 COM 文档模型读取光标前真文（TSF 只暴露组合串，COM 读的是文档本体）——这是预期行为，2026.09.11 起支持
- **第一个词不重排**：重排至少需要 1 个上文 token——光标前还没有任何已上屏文字时（刚装好、新开文档、刚切到某应用）上文为空，引擎保持原候选顺序（属预期）；调试窗口会显示"跳过 ctx_empty"。上屏第一个词后，下一个词即参与重排
- **托盘没有"LLM 重排设置"**：菜单由各应用进程内的 TSF 组件提供，已运行的应用需重启后可见，新开应用立即可见
- **内存紧张（≤4GB）**：模型加载后服务进程常驻约 1 GB（模型 ~500 MB + 推理缓存），低内存机器建议保持关闭（模型路径留空 + 不启用即不占内存）
- **延迟偏高**：看日志（见下）total 是否 ~40ms 量级；~80ms 说明预解码未命中或 `cpu_cores` 超物理核数（设置界面点『实测线程数』取推荐值）

## 日志（排查）

`%APPDATA%\Rime\rime_llm_filter_log.txt`：每次推理一行延迟分解（wait/S1/KV/S2/total/prep/ctx_tok/cand）与事件行（编码/候选/上文/排序结果/来源）；会话启动的 `config:` 行显示当前生效参数与配置来源。反馈问题时附上此文件。

## 实时调试窗口

打字时实时看到：**上文来源**（`tsf` 光标前文 / `com` WPS 文档真文 / `rime` 上屏历史）、**完整上文内容**、每个候选的
**候选总分置前（纯分值），三个分量各自带具体计算过程**（2026-11-11 定案：等宽字体逐位对齐——
同一次调用内每个数值组向最宽者看齐右对齐，整数位数不同不错位；公式不用背、直接在数据里验算），
以及"**为什么没触发**"（编码不匹配 / 上文为空 / 模型未就绪 / 候选不足）、上屏落账（衰减计数前后值）、
编辑键/切窗重置等事件时间线。2026-11-10 起**首选候选不再附加 `AI·` 来源徽章**——来源与分数都在本窗口看，候选窗保持干净。

**候选表 8 列**（命名规则：**原始证据叫「计数」，进公式的叫「得分」**）：

| 列 | 格内样式 |
|---|---|
| `总分` | `-38.095`——融合分纯分值（三项已各自带过程，不重复连加式）|
| `CE` | `-28.075=-(1.00·14.010+1.05·10.130+0.45· 7.617)`——加权 CE = **负的**三分量加权连加（分量是原始交叉熵、正值；负号 = CE 越小分越高）；1.00/1.05/0.45 = 前三 token 位置权重 |
| `衰减词频分` | `13.565=12·ln(1+2.11)`——2.11 = **衰减计数**（eff 原始值）|
| `累计词频` | `2.197=ln(8+1)`——8 = **累计次数**（uni 原始计数）；2026-11-11 起公式不含分母（原 `(uni+1)/(全词数+2万)` 的分母为窗内常数、对排序零影响，位级等价去除）|
| `满` | 两码整句满长组标记（`two_code_sentence` 开启时有意义）|
| `窗` | 1 = 进了 LLM 评分窗；**0 = 尾窗透传（灰字，未进 LLM 评分）** |
| `#` / `词` | 最终输出序位次与候选词（行序 = 输出顺序）|

信息行显示 `输入 / 来源 / 预解 / 耗时 / tick / 全词数 / n / 就绪`
（**全词数** = 累计 unigram 的总词数，打字量指标）。

使用步骤：

1. 托盘右键 → **"LLM 调试窗口"**（或运行安装目录 `WeaselLLMDebug.exe`；语言栏菜单同款入口）
2. 设置界面勾选 **"诊断日志"（debug_fusion）→ 保存并生效**（自动重新部署——此开关同时驱动 `rime_llm_debug.txt` 落盘与实时数据流）
3. 打字即出数据：顶部 = 当前调用的来源/上文/耗时/预解/全词数，中间 = 候选分数表
   （`窗=0` 灰字行 = 尾窗透传、未进 LLM 评分），右侧 = 最近 50 次调用（点选回看），
   底部 = 事件时间线；**暂停**冻结画面、**置顶**方便边打字边看

数据链路：librime `llm_filter` → 命名管道 `\\.\\pipe\\rime_llm_live` → `WeaselLLMDebug.exe` 实时渲染（窗口没开时数据直接丢弃、零开销；广播带 50ms 超时——查看器卡死绝不拖慢打字）。
窗口行协议与插件版查看器（[rime-llm-rerank](https://github.com/zhanghaozhecn/rime-llm-rerank) 仓库 `debug\llm_debug_view.ps1`）一致（V/L/C/S/E/R 六类行：V 版本握手、L 调用头、C 逐候选、
S 跳过原因、E 上屏落账、R 上文重置；字段定义见查看器源码头注释）。

> **评分结果缓存已删除（2026-11-11）**：原先同 (上文+编码) 的评分结果会被缓存复用，实测生产里
> 几乎不命中（每个新词的上文都不同）却要维护一整条失效链，已整体移除——**每次触发都是真实推理**。
> 留下的 **预解**（上文 KV 预解码）是另一回事：上屏后异步把上文 decode 好，下一键直接复用。

## 研究主要结论

重排核心 = 对同码候选做交叉熵评分 `argmax P(wᵢ|上文)`（只排序、不生成、编码无关）。三项关键技术：**分层并行解码**（候选共享上文、≤3 次 decode，与候选数无关）、**预解码 + KV 代次**（commit 后异步算上文，按键延迟 ~43ms）、**CE 位置权重**（前 3 token 按 (1.0, 1.13, 0.61) 加权；尾部外推经端到端扫描证伪删除）。主要数字：

- 首选率 **93.4%**（10 token 上文 / 5 候选，20000 样本），单字 96.8%；模型上限 ~94.3%；
- 0.8B 即最优（2B 仅 +0.3pp 但延迟 3×、体积 2.6×）；10 tok / 5 cand 为性价比最优点；
- 用户词频对数融合（v3 2026-11-06 六维联合标定：`β=12/τ=400` 内置常数，fused = LLM分 + β·log(1+eff) + log(uni+1)；2026-11-05 起退出配置面，原 bigram 项 2026-11-08 退役、δ 0.5→1 同日终审落地，2026-11-11 起公式简化为 log(uni+1)——原 log p1 的分母/δ 均为窗内常数、排序不变量，位级等价去除；用户真实语料评测：纯 LLM 选重率 3.17% → 词频融合 1.90%）：词频无上限、个人证据可翻盘；

完整研究文档（方法细节、扫参全表、词频融合研究）在本地研究资料库 `llm-rerank-research\`（与本仓库同级目录）。

### 真机自动化回归（test_ctx_auto.py）

`scripts\test_ctx_auto.py` 用 SendInput 合成真实键击走完整输入法链路（编码→候选→LLM 重排→上屏，不绕过任何环节），从 `rime_llm_events.txt` 逐词断言上文来源（uia/com/rime）与内容——把退格 / 撤销 / 移光标 / 粘贴等上文信号场景变成一键回归（2026-09-13 真机 12/12 通过，验证插件版信号层修复）：

```bat
python scripts\test_ctx_auto.py               :: 记事本 5 场景（s1 基线/s2 退格/s3 撤销/s4 移光标/s5 粘贴）
python scripts\test_ctx_auto.py -s s2         :: 单场景
python scripts\test_ctx_auto.py --app wps     :: WPS：手动开好空文字文档置前再跑（断言 src=com）
```

运行期间手离开键鼠约 20 秒；自动清旧记事本起新窗口，内置输入法自愈（评分探针 + Win+Space 循环）。三个写进脚本注释的关键事实：满 4 码不自动顶屏（上屏由第 5 键或空格触发，编辑前须先空格顶屏否则删的是编码）；INPUT 结构 union 必须含 MOUSEINPUT（x64 上 40 字节，32B 被 SendInput 静默拒绝）；绝不能 taskkill WeaselServer（丢输入法绑定，恢复只能逐窗 Win+Space）。`--engine source` 切换源码版原生组件日志（`rime_llm_filter_log.txt`，行格式与插件版一致）；`--app wps` 验证 COM 通道（自动找 Office 窗口切前台）。两版回归基线：插件版记事本/WPS 各 12/12、源码版各 11/11（冷启动首词无评分行属行为差异）。
