# rime-llm-ime — 会用 AI 重排候选的小狼毫

## 快速开始（以朙月拼音为例，约 5 分钟）

> 目标：让 **朙月拼音 `luna_pinyin`**（Rime 自带默认方案）用上 LLM 候选重排。换别的方案同理：第 4 步的「编码匹配」按该方案的码长改。

1. **装安装包**：到 [Releases 最新版](https://github.com/zhanghaozhecn/rime-llm-ime/releases/latest) 下载 `weasel-llm-setup-<日期>.exe` 双击（未签名——SmartScreen 弹窗选"更多信息 → 仍要运行"）。全新机器**无需**先装官方小狼毫；已有官方小狼毫则原地升级、不动注册表。装完向导不再问模型（下载在设置界面里）。
2. **打开设置**：托盘小狼毫 → 右键 → **「LLM 设置+调试」**（本来就在运行的应用要重启/注销后才有这个菜单项）。
3. **方案接入**：`方案文件` 选 **`luna_pinyin.schema.yaml（程序）`**（带「（程序）」= 小狼毫自带的预装方案；保存时会先复制到用户文件夹再改，原件不动）。
4. **改参数 + 下模型**：
   - `触发条件` → `编码匹配` 填 **`.+`**（朙月拼音码长 1~6 不等，默认 `.{4}` 不会触发）。
   - `总控` → 点 **『下载模型』**（约 397 MB，ModelScope，断点续传）。
5. **点『保存并生效』** —— 写进该方案的 `llm_rerank:` 节并自动重新部署（缺组件行/配置节时会自动补齐）。
6. **验证**：**连打两个词**——先打 `nihao` 选「你好」上屏，再打 `shijie`，第二个词起重排生效（候选顺序按上文语义变化）。**光标前没有文字时不重排**：重排至少要 1 个上文 token，刚装好（或空文档、刚切窗口）打第一个词时上文为空，引擎直接按原顺序放行，属预期。想确凿看到"上文来源/内容 + 每个候选的分数"：开 [实时调试窗口](#实时调试窗口)（托盘右键 → **「LLM 设置+调试」**，实时数据在窗口右列；需在设置列勾选"诊断日志"并保存生效）。没生效：托盘小狼毫 → **重新部署**。

后续微调都在同一页：改 `触发条件`（`编码匹配` 正则；**勾上 `整句模式` 时该项锁定为 `.{2,}`**；`整句模式` 下方的 **`N-gram 组句候选（含前缀自动确认）` 只在整句模式勾选时出现**）与 `推理规模`（上文 token / 候选数 / **CPU 线程——点右边『实测线程数』让本机实测给推荐值**）→ **保存并生效**；不想用了点 **『剥离』**（就在保存右侧：组件行与配置节一起删，自动重新部署）。

---

LLM 候选重排**源码级集成**进 RIME 小狼毫：本地小语言模型（Qwen3-0.6B Base，约 397MB）依据你正在输入的句子实时给候选排序——刚打过的字决定下一个词谁排第一。全离线运行，无云端无账号，普通 CPU 即可（参考延迟 ~43ms/键）。

## 安装

### 安装包（推荐）

1. 到 [Releases 最新版](https://github.com/zhanghaozhecn/rime-llm-ime/releases/latest) 下载 `weasel-llm-setup-<日期>.exe`（约 10MB）双击（未签名——SmartScreen 弹"Windows 已保护你的电脑"时选"更多信息 → 仍要运行"）。全新机器无需先装官方小狼毫；已有官方小狼毫则原地升级、不动注册。系统要求：Windows 10 或更高（更早版本未验证）
2. 安装向导**不再询问模型下载**（2026-10-01 定案：下载功能统一挪进配置 GUI）：装完在托盘**「LLM 设置+调试」** → **总控** → 点**「下载模型」**（约 397MB，ModelScope 直连，curl 断点续传；落点 = 模型路径框，留空 = `%APPDATA%\Rime\Qwen3-0.6B-Base-Q4_K_M.gguf`；**下载完成后路径框自动填入实际落点**）。**安装过程不写任何配置文件**
3. **在要启用的方案里加组件与配置节**（一次性，三选一）：托盘右键 → **「LLM 设置+调试」** → 选方案点"保存并生效"（缺组件行/配置节时会自动补齐：幂等插入 `llm_filter` + 写入 `llm_rerank:` 配置节 + 自动重新部署）；或运行安装目录下的 `schema_add.ps1`（右键"使用 PowerShell 运行"，交互同上、另支持 CLI 自动化）；或按下文"方案接入"手动加。之后托盘右键 → **重新部署**（用 GUI 保存则自动）
4. 若还没下模型：托盘右键 → **「LLM 设置+调试」** → 总控 → 点**「下载模型」**（或"浏览…"选已有的 `.gguf`；状态行会提示文件是否存在）→ 点**保存并生效**（写入该方案并自动重新部署）
5. 验证：**先上屏一个词**（光标前无文字时不重排——刚装好打的第一个词必然保持原序），再打满 4 码观察候选顺序按上下文变化；确凿验证开 [实时调试窗口](#实时调试窗口)（托盘右键 → **「LLM 设置+调试」**，调试在右列）看逐候选分数

> 已运行的应用需重启（或注销重登）托盘里才有新菜单项；重装/修复 = 重跑安装包（幂等）；输入法图标消失（罕见）→ 右键安装目录下的 `repair_tsf.ps1` → "使用 PowerShell 运行"。

### 设置界面

托盘右键 → **「LLM 设置+调试」**（二合一窗口：左列设置、右列实时调试；也可直启安装目录的 `WeaselLLMSetup.exe` / `WeaselLLMDebug.exe`）。**设置列为单页界面**（与插件版安装器同构）：**方案接入**（方案文件下拉）→ **总控**（启用开关 + 模型路径 + **下载模型** + 模型状态）→ **触发条件**（`编码匹配` 正则 + `整句模式` 复选框 + 仅整句模式勾选时出现的 `N-gram 组句候选（含前缀自动确认）` 复选框）→ **推理规模** → **诊断日志** → 底部 **保存并生效 / 剥离 / 关闭**（底色与插件版统一为白）。

**配置写在方案里**：先在上面选方案文件，再改参数，点"保存并生效"写进该方案的 `llm_rerank:` 节并**自动重新部署**（部署完成即生效）。**"保存并生效"是自适应的**：方案还没接入（缺配置节 / 缺 `llm_filter` 组件行 / 残留插件版组件行）时会先剥净再补齐组件行 + 写入配置节（原「接入 LLM」按钮已并入这里），已接入则只重写配置节；无配置节的方案默认勾选「启用」，点一次保存即完成接入。**"剥离"就在保存按钮右侧**，负责整体移除组件行与配置节。**"下载模型"在模型路径那一行**（curl 断点续传，失败保留 `.download` 分片可续传；**完成后把实际落点自动填回路径框**，留空点下载 = 落默认路径）。**方案下拉列出两处** `*.schema.yaml`：**用户文件夹** `%APPDATA%\Rime`（可写、Rime 优先）与**程序文件夹** `<小狼毫安装目录>\data`（预装方案 luna_pinyin / cangjie5 / bopomofo …，带「（程序）」后缀）；**打开下拉即重扫两处**（外部新增/删除方案后无需手动刷新），界面没有未保存改动时还会重读当前文件。预装方案**写入前会自动复制到用户文件夹**（写程序文件夹既要管理员、又会被下次升级覆盖），程序文件夹里的原件不受影响。若方案文件在界面读入后被外部改过，保存前会弹一次确认。界面**不留日志框**：正常只看状态行，出错才写 `WeaselLLMSetup_error.log`（程序所在目录；该目录不可写时回退 `%APPDATA%\Rime\llm_rerank\`——LLM 数据/日志子目录）。所有参数可选，默认值开箱即用；每项右侧「?」悬停看说明：

> **重排分两层（2026-11-07 起生产语义）**：层1 全体候选先按 用户词频打分重排（同分保引擎序），按 `ce_budget` 预算选评分集进 LLM 评分（1-token 免费）；无 CE 分的候选 CE 取窗内已算 CE 的最低分（排窗底、保留层1 耦合；2026-11-13 起取代「回退后两项和」——旧语义会让无法表示的字以层1 分压过全部负分候选跳首选）；其余候选按层1 序透传 → 层2 对前 k 名做下述三项融合（命中的候选再加 CE 偏置 delta（**只承载负分**，见「词频与词长融合公式」））。选重率（用户真实语料）由 3.73% 降至 1.96%（k=5）。

### 词频与词长融合公式

内置常数 `β=14`（词频权重；2026-11-14 随默认模型 0.5B 重标定，旧 β=12 为 0.8B v3 值）按统一结合公式在**对数域三项相加**，命中 CE 偏置的再加一个 delta（**只承载负分**，正分行不生效；用户 bigram 项已于 2026-11-08 退役——cohort 生产量级评测实证其在真实用户龄几乎无贡献，历史结论见研究资料库）：

```
fused(w) = score(w) + β · log(1 + eff(w)) + log( uni(w) + 1 ) + delta(w)
```

（2026-11-11 起累计项简化为 `log1p(uni)`——原 `log p1` 的分母/δ 均为窗内常数、排序不变量，位级等价去除。）

- `score(w)` = 原始 LLM 分，即候选词在上文条件下的负交叉熵（−CE，对数概率域，越大越好）
- `eff(w)` = Rime 同源的时间衰减计数（librime `algo::formula_d`，与引擎调频 userdb 同一公式）：

```
提交（每次含中文上屏，全局 tick ← tick + 1）:   dee ← 1 + dee · exp((t_w − t) / τ)
查询（打分时刻）:                               eff = dee · exp((t_w − t) / τ)
τ = 400 tick，半衰期 ≈ 277 次提交（v3 2026-11-06 六维联合标定：用户域标定 → wiki 平台内就近点；旧值 800 出自 2026-11-02）
```

- `dee` = 该词的衰减计数，`t_w` = 该词最后提交的 tick，`t` = 当前全局 tick。近期常打的词 eff 高，久未使用自动消退
- **整句模式**（`sentence_mode`，2026-11-22 取代 `two_code_sentence` 两码整句，默认关闭）：**层1 词频在等长词+子词里统一取前 k 进评分窗、窗内全部真算 CE**（2026-11-24 用户定案，取代 2026-11-22「满覆盖优先占满窗」——等长 ≠ 概率高，高词频子词可排在低频等长词之前）；显示序（2026-11-26 恢复先长后短）：[组句首选 1 条] + 窗口候选按字数降序（同字数保持融合序）+ 窗外层1 序，三块输出与子词复用分退役）；**组句候选不占窗席**，走独立 full 任务槽按全句 CE 选 1 条置顶（未落地 = ngram 序首选），其余 4 条不上屏。**开启后编码匹配锁定 `.{2,}`**（2 码起参与重排）。两码一字方案与旧「词长==⌊码长/2⌋」逐位等价（2026-11-07 起取代 elw·span 间接量；2026-11-22 泛化；2026-11-24 统一）

### 方案接入（llm_filter 为显式组件）

`llm_filter` 遵循 Rime 惯例：**方案在 `engine/filters` 里显式列出才参与重排**，未列出的方案完全不受影响。位置由方案与其他 filter 的先后关系决定（重排拿到的是其上方 filter 处理过的候选；一般放在简化/去重类 filter 之后）：

```yaml
# <方案>.schema.yaml
engine:
  filters:
    - simplifier
    - uniquifier
    - llm_filter      # 加这一行，位置按需调整

llm_rerank:            # 参数节（GUI / schema_add.ps1 自动写入，键名同设置界面）
  enabled: true
  code_pattern: '.{4}'   # 整句模式开启时锁定 '.{2,}'
  max_tokens: 20
  ce_budget: 12       # CE2+CE3 总 token 预算（2026-11-26；12 = 旧 6 候选等价成本）
  cpu_cores: 4
  sentence_mode: false
  ngram_group: false  # N-gram 组句候选（含前缀自动确认；2026-11-24 单开关）
  debug_fusion: false
  # model_path: <绝对路径；留注释 = 默认 %APPDATA%\Rime\Qwen3-0.6B-Base-Q4_K_M.gguf>
  # 词频权重 β=14 / τ=400 为内置常数（2026-11-05 起退出配置面；旧 freq_beta 行保存时自动剥除）
```

改完**重新部署**生效（设置界面保存会自动部署）。开/关有两层：去掉组件行（需重新部署）= 该方案彻底关闭；保留组件行、把节里 `enabled` 设为 false = 该方案关掉重排但保留参数。

### CPU 线程数（`cpu_cores`）

默认 4 只是 GGML 默认值，最优值随机器而变。设置界面「推理规模」→ CPU 线程数右边的**『实测线程数』**：用本机模型实测 **4~8 线程**的 **t_cand**（候选段延迟：当前「候选数」个 3-token 候选的两次 decode，预填充不计；约 30 秒，期间请勿打字），弹框给出逐档延迟表 + 推荐值，点「是」把推荐值填进输入框，再点『保存并生效』应用（自动重新部署）。

- **延迟口径 = t_cand**：k 个 3-token 候选、首 token 互不相同（前缀去重失效的最坏情况）；k 跟界面上「候选数」当前值走
- **推荐口径**：取最优延迟 × 1.05 以内**最快**（线程数最小）的档位，且不超过本机物理核——超出物理核的线程是 SMT 兄弟线程，对这个负载几乎不涨分
- **本机不足 5 逻辑核不做实测**，直接取最大线程数
- 实测不写盘：只填输入框，落盘仍走『保存并生效』；关掉界面会一并结束实测进程

## 常见问题

- **Win+Space 没有小狼毫**：设置 → 时间和语言 → 语言 → 中文 → 键盘 → 添加键盘 → 小狼毫
- **某些应用里调试窗口来源显示 `rime`（上屏历史）**：该应用不支持光标文本采集（WPS 表格编辑态、部分 32 位应用），自动用上屏历史，属正常回退
- **WPS 里调试窗口来源显示 `com`**：WPS 文字/演示经 COM 文档模型读取光标前真文（TSF 只暴露组合串，COM 读的是文档本体）——这是预期行为，2026.09.11 起支持
- **第一个词不重排**：重排至少需要 1 个上文 token——光标前还没有任何已上屏文字时（刚装好、新开文档、刚切到某应用）上文为空，引擎保持原候选顺序（属预期）；调试窗口会显示"跳过 ctx_empty"。上屏第一个词后，下一个词即参与重排
- **托盘没有「LLM 设置+调试」**：菜单由各应用进程内的 TSF 组件提供，已运行的应用需重启后可见，新开应用立即可见；装了新版 TSF DLL 后同样要重启应用（安装包提示的"重启电脑"最稳）
- **内存紧张（≤4GB）**：模型加载后服务进程常驻约 1 GB（模型权重 ~0.4 GB + 推理缓存），低内存机器建议保持关闭（模型路径留空 + 不启用即不占内存）
- **延迟偏高**：看日志（见下）total 是否 ~40ms 量级；~80ms 说明预解码未命中或 `cpu_cores` 超物理核数（设置界面点『实测线程数』取推荐值）

## 研究主要结论

重排核心 = 对同码候选做交叉熵评分 `argmax P(wᵢ|上文)`（只排序、不生成、编码无关）。三项关键技术：**分层并行解码**（候选共享上文、≤3 次 decode，与候选数无关）、**预解码 + KV 代次**（commit 后异步算上文，按键延迟 ~43ms）、**CE 位置权重**（前 3 token 按 (1.0, 1.10, 0.60) 加权，2026-11-14 随默认模型 0.5B 重标定，旧 (1.0, 1.05, 0.45) 为 0.8B v3 值；尾部外推经端到端扫描证伪删除）。主要数字：

- 首选率 **93.4%**（历史口径，10 token 上文 / 5 候选，20000 样本），单字 96.8%；模型上限 ~94.3%；
- **延迟分两段计（2026-11-18 定案）**：上文预填充 ≈3.8–6.2 ms/token（0.5B/0.6B/0.8B；
  2B 13.4），候选段最坏情况 ≈14–41 ms/候选；两段是独立预算（ctx 决定预填充量、候选数决定
  按键等待），**研究推荐（2026-11-19，尚未改生产默认）：ctx=20、
  Qwen3-0.6B base Q4_K_M + k=6（100ms / 3.28%）**；0.5B base k=6（102ms / 3.56%）
  为回退档，0.8B base k=4（91ms / 3.55%）仅作规模对照；三个模型均为 official
  **base** 权重自建 Q4_K_M（对话微调版 0.6B 为 4.45%，回 base 后全线最优）；
- 默认 0.6B base（2026-11-19 定案：研究帕累托最优 100ms/3.28%（6 万窗），且比 0.5B base 又快又准；
  旧 0.5B 时代结论「候选段延迟 0.69×、精度代价 −0.12~−0.30pp」为对照 0.8B 所得，0.5B 保留为回退档
  （0.8B 精度拐点可经 `model_path` 自选；**2B 两段延迟均超预算 → 出局**）；
- 用户词频对数融合（2026-11-14 随默认模型 0.5B 重标定：`β=14/τ=400` + kCeW (1.0,1.10,0.60) 内置常数，旧 β=12/(1.05,0.45) 为 0.8B v3 值；fused = LLM分 + β·log1p(eff) + log1p(uni)；2026-11-05 起退出配置面，原 bigram 项 2026-11-08 退役、δ 0.5→1 同日终审落地，2026-11-11 起公式简化为 log1p(uni)——原 log p1 的分母/δ 均为窗内常数、排序不变量，位级等价去除；用户真实语料评测：纯 LLM 选重率 3.17% → 词频融合 1.90%）：词频无上限、个人证据可翻盘；

完整研究文档（方法细节、扫参全表、词频融合研究）在本地研究资料库 `llm-rerank-research\`（与本仓库同级目录）。

### 异步评分（2026-11-22 起，字词/整句两模式统一）

评分移出按键路径（`llm_filter.cc` 异步评分器，与插件版同构）：Collect 每键投递异步任务（指纹 = 归一化上文+候选文本，持久评分线程 + score_batch 每 Step 边界可中断）。**字词模式** submit+wait（≤250ms，与旧同步评分等价，当前词重排零回归）；**整句模式** 窗口 3-token submit + **短预算 wait（默认 150ms，`RIME_LLM_SENTENCE_WAIT_MS` 可覆盖）**，预算内完成即用融合序上屏，超时回退挂账 `async_pending` 由两个收割点回填（Collect 入口 + OnCommit）。**组句全句 CE 走独立任务槽（2026-11-24）**：覆盖式、不可中断，worker 在最后一次按键提交后静默 **250ms** 才开跑，结果落旁路表并触发无按键刷新（不抢占按键路径）。语料 W 行两种形态：正常 `ok`；超时挂账 `skip|async_pending` + 回填 `ok`（flags=`async`）。设计全文见研究库《全拼简拼整句重排-调研与设计》§七/§11.13。

**大词库方案（朙月拼音等）的候选收集限量**（2026-11-22 卡死修复；
2026-11-25 扩到 64 + 覆盖档位配额）：Collect 候选收集 = **64 上限 + 30ms
时间预算**（个数闸管收多少、预算闸管贵不贵）——候选爆炸主因 = **连续声母
简拼**（全拼串 completion 有限、简拼串海量），全量收集曾致单码 0.5-2.25 秒
CPU（enabled=false 对照实测 40 倍差）→ server 消息线程占死 → TSF 管道重连
风暴 → 输入法与宿主应用全卡。深枚举的单次 Peek 内部秒级、预算无法打断——
30ms 阈值须在深枚举发起前拦截。上限 16→64 的依据：**同一码拉 1 条与 64 条
耗时相同**（中位 1.0ms；开销在译文构造，不在逐个取候选），而配额需要更深的池。

**CE 预算准入（2026-11-26，取代 2026-11-25 覆盖档位配额）**：层1 序扫描，
`1-token` 候选免费全收（CE1 即完整分），多 token 候选花 `min(ntok,3)−1`
预算，预算不足进 tail（不评分、不竞争首位）。`ce_budget` 默认 12 = 旧
「6 候选」的等价成本；旧键 `max_candidates` 按 `2×` 映射。依据：wiki 字词
重放 8k 窗，B=4/6/8/9/12 选重率 3.42/3.15/3.02/**2.96**/2.96%，B≥9 贴
全池上限。

**输入闸（2026-11-25 设 30，2026-11-27 放宽 128，学万象 limit_repeated）**：
单段码 **>128 字母**或**连续重复 ≥8** → 不组句、不评分、不确认，按引擎原序
透传（语料 `skip=code_too_long` / `code_repeat`）。放宽依据：增量组句后逐键
成本不再随码长超线性（31–88 字母实测 1.3–3ms/键），限量收集/CE 预算窗也与
码长无关；旧 30 闸在真机高频误伤长句（luna 语料 8.8% 的 W 行被闸，被闸码长
p50=39/p90=47/max=54），被闸段只剩引擎原序。128 = 真机被闸 max 54 的 2.4 倍、
与组句检查点上限对齐。`code_repeat` 独立保留。A/B：`RIME_LLM_GATE_LEN=30`。
另：C++ 内置
默认模型路径已补齐 2026-11-19 定案（Qwen3-0.6B——此前仍指 qwen2.5-0.5b，
无 model_path 的方案会加载不存在的文件，failed to load model 死循环）。

**引擎滑窗 `translator/seg_window_syllables`（2026-11-23 实现，默认 0 关）**：
组句只在前 N 个音节位置内进行（千问 fork 同名参数思路）。实测长串（20 键）
开窗前后耗时均 58ms（组句不是长串成本主因），且前缀截断使长句候选劣化（末词
被迫在窗口边界结束）→ **默认不启用**，参数保留给阶段三前缀整句/词串。

### N-gram 组句候选 + 无按键刷新（2026-11-23 第②段；2026-11-24 phrase-only 定案）

`llm_rerank/ngram_group` 打开后，`llm_ngram.cc`（万象 LTS `.gram` + 万象
词库词级 beam，与插件版同构、与研究脚本 `eval/tools/sentence_gen_gram.py`
逐句对拍 100/100 一致）生成 **top-20 整句候选**（2026-11-24：topk 5→20，
供 lead 概率质量），在 `Collect` 里前置注入（同文本去重，`engine_top` 保持
引擎原序），后续层1（等长词+子词统一取窗）/3-token 评分/指纹沿用既有逻辑。
**组句不参与评分**（phrase-only）：显示只置顶 ngram 序第 1，其余 19 条不上屏；
**全句 CE / full 任务槽 / 250ms 静默门已退役**（`score_full_batch` 保留为
回滚参照、无调用点）。生效门 = 整句模式 + 方案输出简体（`engine/filters` 含
`simplifier`；`simplifier/option_name` 存在时还要求该开关为开——朙月这类
**无 option_name 的恒转换** simplifier 也算输出简体）；
资产在用户目录 `llm_ngram\`（或 `RIME_LLM_NGRAM_PATH` / `RIME_LLM_NGRAM_DICT`），
索引缓存 `llm_rerank\ngram_lex\<方案>.bin`（首次约 5 秒、之后 mmap 近 0 秒）。
生产参数 14–16ms/句、wiki hit@5 73%/61%；topk 20 实测 4.0→4.1ms/窗。
**增量组句（2026-11-27，与插件版同构）**：逐键续打跨键复用逐码位剪枝 beam
（`GenerateCached`，位置 i 的剪枝结果只依赖码前缀 + 上文尾 + 参数），结果
与全量**逐位一致**（插件侧 200 句 × 6,741 前缀步对拍 fail=0），逐键开销
4–15ms → ~1.2–2ms 且不随码长超线性涨；有效性 = 纯前缀延伸 + 同上文尾 +
同参数，不满足自动回落全量；A/B `RIME_LLM_NGRAM_INCR=0`。对拍工具在插件
仓（`cpp/ngram_parity.lua` 的 `NGRAM_MODE=incr`）。
生成结果先过**完整覆盖校验**（词序列须从码位 0 连续覆盖到码末）才允许注入。
切片口径：`Collect` 收到的 `input_` 已经是活动段切片（`Apply` 按段边界截好），
**不得再按 `seg_start_` 二次截取**——`Select` 之后段的 start/end 仍是原串坐标，
二次切片会得到错码并产出垃圾候选。

**整句 CE 已退役（2026-11-24）**：`score_full_batch`（评分窗候选一个 batch
一次 forward 算完整句条件 CE）保留为回滚参照，**当前无调用点**；组句不再
排序，显示 = ngram 序首选。异步任务只剩 3-token 一种口径，指纹尾标记恒为
`\x1b`。

**无按键刷新（源码版专有）**：`RimeRefreshComposition(session_id)`（→
`Context::RefreshNonConfirmedComposition`）+ 新 IPC `WEASEL_IPC_REFRESH`
（`Client::Refresh` → `ServerImpl::OnRefresh` → `RimeWithWeaselHandler::Refresh`）
+ WeaselTSF 组合期 **120ms 定时器** —— **2026-11-23 深夜改为隐藏消息窗口 +
窗口定时器**（`CreateWindowExW(HWND_MESSAGE)` + `SetTimer(hwnd,…)`）：原先的
线程定时器（`SetTimer(NULL, this+1, …)`）在本机 TSF 线程上 **SetTimer 成功但
WM_TIMER 永不派发**（`%TEMP%\weasel_tsf_timer.log` 实锤），表现为"停手后
永不刷新、LLM 结果与前缀确认都不上屏"；窗口定时器的 WM_TIMER 走窗口过程，
随应用自身的 `DispatchMessage` 派发。`_FinalizeComposition` 停表。
**门控（2026-11-24 更新）= `RimeLlmPendingConfirm()`**——整句 CE 退役后
`RimeLlmAsyncRevision()` 恒不前进（槽保留给 API 稳定、weasel 侧比较逻辑
不变），刷新只在"有挂起的前缀确认"时重译；**确认只能在刷新路径执行**，
按键路径的 `update_notifier` 里 `ctx->Select` 会让该键异常无响应、TSF 卡死
（2026-11-23 真机事故）。**响应体必须每次写**（客户端紧随的 `DoEditSession`
会解析该缓冲，留旧内容会复活过期候选表）。**候选遍历必须正确置 exhaustion
（2026-11-24 修）**：`Menu::Prepare` 的循环是
`while (候选数 < 请求数 && !translation->exhausted())`，自定义 `Translation`
取尽时必须 `set_exhausted(true)`——`LlmRerankTranslation` 此前漏了这一步，
请求数超过提供数时 `Peek()` 返空 + `Next()` 原地 false ⇒ 无限循环：服务满
CPU 空转、IPC 全堵、**整机只剩任务管理器能动**（v2026.11.23-2 及更早版本
均带此缺陷，2026-11-24 修复）。

**前缀确认（2026-11-24 合并单一路线）**：唯一 pending 生产者 = 组句给文本 +
窗口融合序投票——① 组句侧 **top-20 按 lead 分组 softmax，P(lead) ≥ 0.95**
（研究库：同精度下召回比"5 条 lead 全一致"高 51%；阈值 0.90 落进双峰低谷，
0.95–0.97 才稳）；② 该 lead 文本必须是**窗口融合序第 1** 且 span 对齐
（文本一致铁律：同码同长同音字不得按区间捡，宁可不确认、不可错确认）；
③ **音节守卫**（2026-11-24 标定 + 真机定案）：**确认后剩余 ≥2 音节**
（单字 lead 无例外——`xiazai` 在 `xia` 确认「下」会把 2 字词拆开）——组句
句子字数 = 音节数，码数在简拼/双拼/混拼下不是通用单位（旧「≥6 码 / 余 ≥4 码」退役）。**窗口路径 A（margin）、句级 CE 序分支、
θ 与单字倍数全部退役**；组句返回空（码切在音节中间，占 39.5%）的窗不再
自动确认。链式确认成立但**不放松守卫**：每次确认后刷新在更短的码上重新
判门（静态链实测 1.3% 的状态可再次确认、23/23 全对）。

**无头探针验证**（`scripts\rime_refresh_probe.cpp`，须从 `bin\` 运行——
`rime.dll` 依赖同目录 `opencc.dll`；2026-11-24 改为轮询
`RimeLlmPendingConfirm()`）：`detianqi` + 上文「今天」→ top-20 组句（lead
「的」，P≥0.95）→ 窗口融合序第 1 = 「的」→ 挂起 → `RimeRefreshComposition`
执行确认 → **组合区变 `的tianqi`（rev 恒 0、挂起驱动刷新）**。探针不传
`traits` 会退化到 `shared="."`（每键都不吃、候选恒 0），必须显式给
shared/user 目录。

**已知待办**：GUI/安装器 `ngram_group` 开关与万象资产可选下载仍属下一阶段；
真机打字手感（确认时机/链式确认）待用户复核。

### 整句词频归因（2026-11-26，与插件版同构）

整句模式一次 commit 上屏的是整个句子，把整句记成词条 = 键永不复现（实测
luna_pinyin 账本 8.4% 条目 ≥6 字，多段提交键还错配为「整句文本⊕尾段码」）。
`OnCommit`（`Context::Commit` 的 `Clear()` **之前**触发，composition 与
input 仍可读）按「组合区已确认段」逐词归因：

- **普通段 / 前缀确认词** = 单词条 `(词, 段码)`；**组句段** = 组句词路径
  （`Sentence.words` 的 `code_end` 偏移，注入时登记 `g_ng_paths` 环形表
  cap 16，text+code 双键取回）按段码切片每词一条；
- **N 词共享提交级 tick**（`user_stats_bump_at` 显式 tick，一次 commit +1；
  门检在 `++g_user_tick` 之前——被拒提交不推 tick 的原语义保持）；
- **整句键不再入账**；四重校验不过（Σ段文本≠提交文本 / 段码非纯小写 /
  full_code 与 live 码无后缀关系 / 词路径覆盖断裂）→ 回退旧行为整句入账；
- **C 行 v8 尾字段** `path` = `词:码/词:码/…`（归因 C 行码 = 各段码拼接 =
  完整提交码；`write_c` ref 匹配放宽为窗码是提交码**后缀**即命中）；
- **退款**：`CommitRec` 组记录，一条 M 整组退款（RF 行带 `n=词数`）；
- A/B：`RIME_LLM_SENTENCE_ATTR=0` 回退旧行为。

### 构建步骤

weasel 基底为 **0.17.4 release tag**（勿用 master——IPC 协议有差异，混用会输入失效）。相对上游的完整改动清单与维护陷阱（rime_api.h 双副本同步、include 路径等）见项目记忆 `memory\upstream-diff.md`，不在本文展开。

```bat
:: 0. 首次：boost + librime 依赖
weasel\install_boost.bat
cd librime
git submodule update --init --recursive
build.bat
cd ..

:: 1. llama.cpp MT 静态构建（任选目录，记为 <llama目录>）
git clone https://github.com/ggml-org/llama.cpp <你的 llama 目录>
cd <你的 llama 目录>
cmake -B build-mt -A x64 -DCMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded ^
      -DLLAMA_BUILD_TESTS=OFF -DLLAMA_BUILD_EXAMPLES=OFF -DLLAMA_BUILD_SERVER=OFF
cmake --build build-mt --config Release
cd ..

:: 2. rime.dll（llm_filter 链接 llama）
set LLAMA_ROOT=<你的 llama 目录>
scripts\cmake_rime.bat          :: → librime\build\*.sln
scripts\build_rime.bat          :: → librime\build\bin\Release\rime.dll

:: 3. weasel（首次：weasel\weasel.props 从 template 复制并设 BOOST_ROOT；
::    rime.lib 入库用 scripts\gen_rime_lib.bat）
scripts\build_tsf.bat           :: x64 TSF → weasel\output\weaselx64.dll
scripts\build_server.bat        :: → weasel\output\WeaselServer.exe
scripts\build_llm_setup.bat     :: → bin\WeaselLLMSetup.exe
:: 32 位 TSF（可选）：scripts\build_boost32.bat + scripts\build_tsf32.bat
```

`cmake_rime.bat` 的依赖探测优先 `deps\prebuilt\`（本机布局），回退 librime 官方安装位置；`RIME_DEPS`/`BOOST_ROOT`/`LLAMA_ROOT` 环境变量可覆盖。仅 CPU 路线。

> **新增 librime 源文件后必须重跑一次 configure**：`src/CMakeLists.txt` 用
> `aux_source_directory(rime/gear …)`，文件列表是 configure 期快照；且
> `scripts\build_rime_inc.bat` 直接调 `rime.vcxproj`，不会触发 ZERO_CHECK。
> 例：2026-11-23 加 `llm_ngram.cc` 后先 `cmake -B build -S .` 再增量编译。

### 打包

产物放进 `bin\`（32 位 TSF 改名 `weasel32.dll`；`opencc.dll`/`vcomp140.dll`/`WinSparkle.dll` 从官方安装目录拷入）→ `installer\make_installer.ps1` 同步载荷到 `installer\source\` → `scripts\build_pkg.bat` 编译 → `installer\dist\` 下的 setup.exe。**载荷变动后必须 `dumpbin /DEPENDENTS` 复核全部导入**（流程与教训见项目记忆）。
